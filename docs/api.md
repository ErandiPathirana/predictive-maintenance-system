# API documentation

Interactive documentation is generated by FastAPI: **Swagger UI at `/docs`**, ReDoc at `/redoc`, machine-readable spec at `/openapi.json`
(a snapshot is in `docs/openapi.json`). Every request and response schema is listed in `docs/api-schemas.md`.

## What a response means
* `predicted_condition` is a **predicted condition class** (Normal / Alert / Danger). It is **not a confirmed machine failure**.
* `scores` are model outputs that sum to 1. They are **not calibrated probabilities** (calibration was not evaluated), and
  `scores_are_calibrated_probabilities` is always `false`.
* `demonstration_only: true` means the label provenance is undocumented or the bundle is a smoke test. Do not use such results for decisions.
* `input_warnings` list readings outside the range seen **in training**. They are not engineering limits or alarm thresholds, and they do not block a prediction.

## Endpoints
| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | Is the API up? Is the model loaded? Is the database reachable? (no API key needed) |
| GET | `/api/model-info` | Bundle version, classes, provenance flags, honesty notes |
| GET | `/api/features` | The 14 inputs in the order the model expects |
| GET | `/api/template.csv` | Empty CSV template with the correct columns |
| POST | `/api/uploads/validate` | Dry-run check of a CSV: nothing predicted, nothing stored |
| POST | `/api/predict` | One motor reading to a predicted condition (stored in history) |
| POST | `/api/predict/batch` | Uploaded CSV to a predicted condition per row (all-or-nothing, stored in history) |
| GET | `/api/predictions` | History. Filters: `motor_id`, `record_id`, `batch_id`, `predicted_condition`, `date_from`, `date_to`, `measured_from`, `measured_to`; paging `limit` (1-500), `offset` |
| GET | `/api/predictions/{id}` | One stored prediction |
| GET | `/api/batches` | Recent CSV uploads |
| GET | `/api/reports/predictions.csv` | CSV export of results, same filters as the history |

## CSV upload format
Header (exact, case-sensitive names): `record_id, motor_id, measured_at` (optional) and the 14 feature columns from `/api/template.csv`.
`condition_label` is tolerated and **ignored**. The easiest valid file is `motor_clean_working_copy.csv`, written by the notebook.
* IDs: 1-64 characters from letters, digits, `.`, `_`, `-`; `record_id` unique within the file.
* Numbers: plain decimals only (`12.5`, `-3`, `1.5e-2`). Empty, `nan`, `inf`, text, thousands separators and decimal commas are rejected. Missing readings are never filled in.
* `measured_at`: ISO 8601 (`2025-04-01 07:20:00`) or the training-data format `M/D/YYYY H:MM`, consistent on every row. Day-first dates are not guessed.
* Limits (configurable): 2 MB, 5,000 rows, 60 columns. Only `.csv` text files; spreadsheets, archives and executables are refused.
* **All-or-nothing:** if any row is invalid, **no** predictions are made and nothing is saved. The 422 response lists up to 50 problems (`row`, `column`, `problem`) and the true total.

## Errors (all endpoints)
```json
{ "error": { "code": "machine_readable_code", "message": "Plain English.", "details": { } } }
```
| HTTP | `code` | Meaning |
|---|---|---|
| 401 | `unauthorized` | `API_KEY` is set and `X-API-Key` is missing or wrong |
| 404 | `not_found` | No such prediction |
| 413 | `file_too_large` | Upload exceeds `MAX_UPLOAD_BYTES` |
| 415 | `unsupported_file` | Not a `.csv`, wrong content type, or binary content |
| 422 | `invalid_request` | Body/query is not in the expected format (wrong types, extra fields, bad dates) |
| 422 | `invalid_sensor_readings` | Single prediction: missing, unknown or non-finite readings |
| 422 | `invalid_csv` | CSV content problems (see `details.issues`) |
| 422 | `invalid_query` | Inconsistent filters (e.g. `date_from` after `date_to`) |
| 503 | `model_not_ready` | No valid model bundle is loaded (only possible when `REQUIRE_MODEL_AT_STARTUP=false`) |
| 500 | `prediction_failed` / `internal_error` | Details are logged, never returned |

## Testing in Swagger UI (step by step)
1. Start the backend and open <http://localhost:8000/docs>.
2. If you set `API_KEY`, click **Authorize**, enter the key, and click Authorize again.
3. **Health:** open `GET /api/health` > *Try it out* > *Execute*. Expect `"model_ready": true`, `"database": "ok"`.
4. **Model info:** `GET /api/model-info`. Read `demonstration_only` and `notes`.
5. **Features:** `GET /api/features` shows the 14 inputs and their units.
6. **Single prediction:** `POST /api/predict` > *Try it out*. Paste a body like the one below with your own numbers for all 14 readings, then *Execute*.
   ```json
   { "record_id": "TEST-1", "motor_id": "TESTMOTOR", "readings": { "de_h_velocity_mm_s": 0.0, "...": 0.0 } }
   ```
   (Use `GET /api/features` for the exact names. Omitting one returns a clear 422.)
7. **CSV:** `GET /api/template.csv` > *Download file*. Fill rows in a spreadsheet, save as *CSV UTF-8*. Or use `motor_clean_working_copy.csv`. Then `POST /api/uploads/validate` > *Choose File* > *Execute*. When `valid` is true, repeat with `POST /api/predict/batch`.
8. **History:** `GET /api/predictions`, try `motor_id`, `date_from` (`2026-01-01`), `predicted_condition`.
9. **Export:** `GET /api/reports/predictions.csv` > *Download file*.
